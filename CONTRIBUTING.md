# Contributing

Thanks for considering it. Two things to know first.

**Open an issue before a PR.** Tell me what's broken or what you want to add. Saves both of us time if I have thoughts before you write code.

**Skills should be skills people actually use.** If you want to add one, tell me a real workflow it solves for you. The handoff skill is in here because I bounce between 10+ projects a week and was losing track. A skill that solves a hypothetical problem is harder to maintain than one with a real owner who uses it daily.

Beyond that:

- Layout: `skills/<name>/SKILL.md`. Frontmatter with `name` and `description` at minimum.
- Description should be specific enough to trigger correctly. Include trigger phrases and explicit non-triggers if it's easy to confuse with another skill.
- Add an `example-*.md` in the skill folder if the output format is non-obvious.
- Sanitize. No personal paths, API keys, or company-specific references.

That's the whole bar. Don't overthink it.
